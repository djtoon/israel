# Localisation (i18n): how text is translated

English is the source language. Hebrew (`he`) is the first translation. The engine is `scripts/ui/l10n.gd` (`L10n`) plus `scripts/ui/l10n_translation.gd`, a Translation registered with Godot's TranslationServer. That means every Label, Button, tooltip, RichTextLabel, OptionButton item, window title and Label3D asks L10n for its text, and the custom-drawn HUD and map banners go through `UIKit.text()`, which calls `L10n.t()`. **Translators never touch code.**

There are two kinds of files:

| What | Where | Shape | Who fills it |
|---|---|---|---|
| UI text (HUD, menus, windows, tooltips, tutorial, How to Play, notifications, sim messages) | `game/i18n/he/*.json` | flat `{ "English": "עברית" }` | ui-i18n (done for v3) |
| Data text (events, forks, techs, civics, buildings, units, districts, policies, governments, actors, diplomacy, endings, projects, wars, places...) | `game/data/i18n/he/<source>.json` | `{ record: { field: { "en", "he" } } }` | translator agents, one file each |

The glossary of standard Hebrew forms is `game/i18n/glossary_he.json`: style rules, game terms, people, parties, institutions, operations, wars and treaties, countries, regions and places. **Use it for every proper name and game term.**

## 1. Data files: `game/data/i18n/he/<source>.json` (for translators)

`tools/i18n/make_skeletons.py` generates one file per source:

| File | Made from |
|---|---|
| `events` | `data/events.json` (`title`, `summary`, choice `label`/`note`, `affected_populations` notes...) |
| `forks_<range>`, `forks_v3_<range>` | `data/forks/<range>.json` (`title`, `text`, option `label`/`note`/`advocate`...) |
| `wars` | all of `data/wars/*.json` (the record is the war id) |
| `techs`, `civics`, `buildings`, `units`, `districts`, `policies`, `governments`, `actors`, `diplomacy`, `endings`, `projects`, `difficulty` | the file of the same name |
| `choice_terms` | `data/choice_terms.json` (stream labels) |
| `art_manifest` | portrait names and roles, illustration titles |
| `places` | city names (`cities/<id>`), map places, natural wonders, regions and border eras (from `map.json`) |

Each file looks like this:

```json
{
 "_meta": {"source": "events", "lang": "he", "entries": 1186, "translated": 353, "generated": "...", "format": "..."},
 "evt_1948_independence": {
  "title":   {"en": "Declaration of the Establishment of the State of Israel", "he": "הכרזת העצמאות"},
  "summary": {"en": "David Ben-Gurion read the Declaration ...", "he": ""}
 },
 "fork_1948_army": {
  "options.0.label": {"en": "One army under civilian command", "he": ""}
 }
}
```

- **The record key** is the record's `id`. In files with several collections it is `<collection>/<id>`, for example `buildings/granary` or `terms/3` (a list index where there is no id).
- **The field key** is the field's path inside the record. List items are numbered from 0, for example `choices.1.label` or `tradeoffs.0`.

**What translators do:**
1. Fill every empty `"he"`, and leave `"en"` exactly as it is. The game matches the English text it is about to show against `"en"`, so a changed `"en"` breaks the match.
2. Keep placeholders in curly braces as they are, for example `{end}`, `{name}` or `{0}`. You may move them within the sentence: `"By {end} your Israel is a Secure State."` becomes `"עד {end} ישראל שלכם היא מדינה בטוחה."`.
3. Keep numbers, dates, signs, `%` and units (`km`, `m`) as they are. Write dates the Hebrew way: `14 May 1948` becomes `14 במאי 1948`.
4. Keep any BBCode tags in square brackets, for example `[b]...[/b]`.
5. Translate names with the glossary forms (people, parties, places, operations). Where the glossary has no form, use the form the Hebrew press uses. Never invent a new Hebrew name for a real place.
6. Keep the neutrality of the English. Do not add or remove political framing, and translate casualty and displacement figures literally.
7. **Do not translate** the following, which are never in these files: source citations (`cite`, `quote`, `claim`, `url`), ids, file paths, and the 7 October 2023 memorial (`data/ending_oct7.json`). The memorial stays in the user's own English unless the user adds `paragraphs_he` to that file.
8. If you leave a translation empty, the game shows the English.
9. If you are unsure about an entry, still translate it and add `"check": "<why>"` next to `"he"`. The game ignores extra keys.
10. Keep the file valid UTF-8 JSON (`python -m json.tool <file>`). Each file can be translated independently and in parallel with the others.

**Stale entries.** When the English data changes, re-run `python tools/i18n/make_skeletons.py`. It keeps every existing translation. If an entry's English changed, the old translation stays but the entry is marked `"stale": true`, and the game ignores stale entries. After re-checking the translation, delete the flag. `--check` prints coverage without writing anything.

**Lookups.**
- The game finds data text by its English, so a string from the data shows in Hebrew wherever it appears: popups, the Civilopedia, logs, map banners and tooltips.
- Code can also ask for one field directly: `L10n.data("events", "evt_1948_independence", "summary", english)`.

## 2. UI catalogs: `game/i18n/he/*.json`

These are flat objects, `{"English": "Hebrew"}`, merged in file-name order (a later file overrides an earlier one). A key that starts with `_` is a comment. An empty value means "not translated yet".

- **Exact keys:** `"End turn": "סיום התור"`. Lookups also ignore case (`"SETTINGS"` finds `"Settings"`) and surrounding whitespace, bullets and trailing punctuation (`"  Gold:"` finds `"Gold"`).
- **Pattern keys** match text that the code has already put together:
  - `{0}`, `{1}` or `{name}` matches any text, and that text is itself translated. For example, `"Research: {0}"` maps to `"מחקר: {0}"`, so `"Research: Agriculture"` becomes `"מחקר: חקלאות"`.
  - `{#0}` matches a number (`12`, `−3`, `+4.5`, `1,234`, `40%`) and keeps it as is. For example, `"Turn {#0}"` maps to `"תור {#0}"`.
  - The Hebrew may reorder the placeholders.
  - Patterns with more fixed text win over vaguer ones.
  - Write placeholders as they appear in the finished text. GDScript `%s` / `%d` become `{0}` / `{#0}`, and `%%` becomes `%`.
- **Line by line:** text with line breaks is translated one line at a time, so a key is never more than one line.
- **BBCode:** a line with tags is first looked up whole, tags included. That is best for prose: the key `"Click it (or press [b]Enter[/b]) to jump there."` maps to `"לחצו עליו (או הקישו [b]Enter[/b]) כדי לעבור לשם."`. With no whole-line match, the line is translated one run at a time, the text between tags. So `"[b]%s[/b] joins the coalition"` works with the keys `"{0}"`, a data name that is found by itself, and `"joins the coalition"`.
  - Colour tags are written with the standard hexes (`#9fe07a` good, `#ff8f7a` bad). The colourblind palette is handled for you.
- **Splitting:** with no other match, text is split at ` — `, ` · `, ` | `, `; `, `: `, `. `, `, `, at a trailing `(...)` and at line breaks, and each part is looked up. A key for the whole sentence is always better.
- **Files:**
  - `ui_core.json` holds common words, yields, dates and structural patterns;
  - `ui_<screen>.json` holds each screen's strings;
  - `sim.json` holds messages written by `scripts/sim/` (notifications, reasons, effect lines).

## 3. Right to left

- In Hebrew the screen layout keeps its English positions, so the Civ-style HUD, the top bar and the docked side panels still fit together.
- Everything inside a container is laid out right to left: window bodies, rows, cards and lists. Rows mirror, text aligns right and scroll bars move left. `L10n._on_node_added` does this for every Control whose parent is a Container.
- Mark a node `L10n.keep_ltr(node)` to keep it left to right (the English memorial, URLs).
- **Text direction.**
  - Label text direction is automatic, so Hebrew reads right to left and English names and numbers inside it stay readable (Unicode bidi).
  - Rich text in right-to-left content uses the layout direction (`TEXT_DIRECTION_INHERITED`), so every paragraph is right-aligned.
- **Bidi marks.** `L10n.translate()` adds invisible marks to each line it returns in Hebrew. A Hebrew line starts with RLM (U+200F). A line still in English (data waiting for its translator) is isolated left to right (U+2066 ... U+2069), so its full stop stays at its end.
  - Use `L10n.plain()` for text that is stored rather than shown, such as a default save name.
- **Locale.** The engine locale stays `"en"`: the Hebrew Translation is registered under it. So text with no letters of its own, such as `+3`, `4 / 5.0` or `−6.0`, stays left to right instead of taking the Hebrew default. `L10n.lang` is the language.

## 4. Fonts

- **Hebrew fallbacks.** Cinzel and Crimson Pro have no Hebrew, so `L10n.install_fonts()` gives every game font a Hebrew fallback:
  - **Frank Ruhl Libre** (serif, variable weight) for the serif faces;
  - **Noto Sans Hebrew** for the engine default.
- **Licences.** Both are OFL; the licences are in `assets/fonts/OFL_*.txt`.

## 5. Testing

- **Command line.**
  - `--lang=he` runs the game in Hebrew for that run without changing the player's setting.
  - `--ui-test=<dir> --lang=he` is the Hebrew UI test.
- **What the Hebrew UI test checks.** Every visible text on every screen it opens goes through `L10n.audit()`. A failure is either of these:
  - UI text with no translation;
  - a window off screen at 1280x720.
- **What it does not flag.**
  - Data text that is waiting for its translator is listed as "data pending", not a failure.
  - Names and allowed Latin tokens (key names such as Ctrl or F1, licence names, URLs) pass.
  - A node marked `L10n.skip(node)` is not checked (licences, photographers' names, the memorial).
- **Output.** The run writes `i18n_missing.json` (untranslated UI text, ready to paste into a catalog) and `i18n_pending_data.txt` to the test folder.
